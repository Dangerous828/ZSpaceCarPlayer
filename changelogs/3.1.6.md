## 🎯 这一版要解决的问题

选歌是这个 app 的主路径，但 54 首的歌单**一屏只见 5 行**，滑十几屏才能碰到目标歌；同时一屏里出现六个渐变色块互相抢视线。

先量清楚病因（吉利 8600 是 1920×720 px @ density 1.0 → `sw=720dp`，所以 `values-sw720dp` 这一档才是真车生效值）：

| 项 | 改前实际值 | 占用 |
| :--- | :--- | :--- |
| 顶栏 `topbar_h` | 96dp | 高度 13% |
| 列表行 `row_h` | 104dp | 一屏只放得下 5 行 |
| 其中首字色块 `thumb` | 72dp 见方 + 36sp 字 | 行高 69%、行宽 72dp |
| 列表栏宽度 | `weight 5.2` ≈ 998dp | — |
| 进度条轨道 `seek_track_h` | 5dp | 行车中点不中 |
| 搜索占位 `search_w` | 380dp | 顶栏 38% 宽 |

关键一条：**那个首字色块展示的就是歌名第一个字，而右侧歌名本来就完整显示了它**——信息量为零，却吃掉每行近七成高度。

## 🔧 改动

### 1. 列表密度（`layout/item_song.xml` + `ui/SongAdapter.java`）

- 移除首字色块 `tvThumb`，连带删掉 `THUMB_BG` 六色渐变表与 `firstDisplayChar()` 取首字函数（`bg_thumb_*` drawable 保留，歌单网格卡片 `CategoryAdapter` 仍在用，那里彩色有辨识价值）。
- `row_h` 104dp → **78dp**。
- 正在播的行仍由左侧 3dp 青绿 `accentBar` 唯一标识，不再依赖色块颜色。

### 2. 分栏比例（`layout/activity_main.xml`）

列表栏 `weight 5.2 → 6.0`（≈998dp → ≈1152dp），右栏 `4.8 → 4.0`（≈922dp → ≈768dp）。歌名与艺人名截断概率下降；右栏 768dp 放 46sp 歌词行约 16 个汉字，够用。

### 3. 字号阶梯与触控目标（`values-sw720dp/dimens.xml`）

| 角色 | 改前 | 改后 | 说明 |
| :--- | :--- | :--- | :--- |
| 歌名 | 28sp | 26sp | 仍远高于手机档 |
| 艺人 / 时长 | 22sp | 18sp | 守住车内 16sp 可读下限 |
| 流派标签 | 19sp | 16sp | 同上 |
| 收藏按钮 | 62dp | 52dp | 仍 >48dp 触控下限 |
| 进度条轨道 | 5dp | **10dp** | 加粗一倍 |
| 进度条滑块 | 18dp | **30dp** | 行车中点得中 |
| 播放主按钮 | 60dp | 64dp | 主次两档：64 / 56 |
| 上一首/下一首 | 52dp | 56dp | 与次档统一 |
| 搜索占位 | 380×58dp | 210×48dp | 顶栏不再被输入框吃掉三分之一 |
| 顶栏 | 96dp | 84dp | 让给列表 |

### 4. 明确没做的两件事

- **配色体系不动**：`Night-Drive Teal`（`#080C12` 底 + `#30DDC2` 青绿 accent + 三级 ink）本身是成体系的，问题从来不在色板，而在六个渐变色块同时出现在一屏。
- **顶栏连接状态胶囊保留**：它显示的是"连接中/登录中/同步中/无网络/连接超时"的实时状态，不是装饰性占位；截图里看到"连接超时"是当时真连不上。

## 📐 预期效果（几何计算值）

```
一屏行数 = (720 − 84 顶栏 − ~54 列表标题行) / 78 ≈ 7.4  →  7 行（原 5 行，+40%）
行内不裁字 = 26sp×1.3 + 18sp×1.3 + 2dp ≈ 59px < 78dp  →  留 19px 呼吸
```

## ⚠️ 验证边界（必须说清）

**本版只做了编译与几何验算，没有实车观感验证。** 车机是 API 18 / density 1.0 的 1920×720，Mac 侧没有等价模拟器可截图，所以"一屏 7 行""不裁字""点得中"都是按 dp 算出来的结论，不是看到的结论。真车效果以下面这份清单为准。

`clean testDebugUnitTest assembleDebug` 通过，349 条 host JVM 单测全绿（本版为纯呈现层改动，无新增逻辑判据，故未新增测例）。

## 🚗 实车验收清单

1. 设置页「检查更新」拉到 v3.1.6 (vc10)，`dumpsys package` 确认 `versionCode=10`。
2. 打开任一歌单，数一屏能看到几行（预期 7 行；若仍是 5 行说明真车没命中 `sw720dp` 档，要回查 density）。
3. 确认歌名与艺人名**没有被上下裁切**（行高压到 78dp 后这是首要风险点）。
4. 行车状态下试拖进度条，确认 10dp 轨道 + 30dp 滑块点得中、不误触。
5. 确认正在播的那一行仍有清晰的左侧青绿指示条，且列表里不再出现彩色方块。
6. 顶栏「搜索」按钮收窄后，确认仍能一眼找到、点开输入法正常。
7. 右栏变窄后播一首带长歌词的歌，确认歌词不折行错位、字号仍够读。
