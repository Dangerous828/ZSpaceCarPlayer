# ZSpaceCarPlayer v3.2.0 Changelog

**版本：** v3.2.0 (versionCode 11)
**更新日期：** 2026-09-24
**适配系统：** Android 4.3 / API 18 (吉利 8600 经典固件)

> 界面从「左列表 + 右播放面板」改成「全宽列表 + 底部通栏播控」，配色换成亮底并新增暖墨夜间档；同时把列表顺序收成唯一来源，修掉播放队列与左侧列表分叉。

---

## 🎯 这一版要解决的问题

1. **强光下读不了。** 原 `Night-Drive Teal` 深色底在白天车内会反射成镜面，图标和文字一起被洗掉。
2. **播控离司机太远。** 播控区在右栏，而司机在左侧（左舵车），换歌要伸手横穿大半个屏幕。
3. **播放不跟左侧列表走。** 队列和屏幕上是两份东西。这一条本版是**查清了根因并改了判据**，详见下节。

## 🔧 改动

### 1. 版式：全宽单栏 + 底部通栏（`layout/activity_main.xml`、`layout/item_song.xml`）

右栏取消。曲名、当前歌词行、进度、播控键全部收进底部 140dp 通栏；歌名与歌手从上下两行改成**同一基线**，这样 72dp 行高里放得下 27sp 歌名——两行版式要放大歌名就得加行高，一屏会从 6 行掉到 5 行。

纵向预算是闭合的，四个高度只能整体平移：

```
顶栏 88 + 列头 44 + 列表 6×72=432 + 播控条 140 + 条下留白 14 = 718 ≤ 720
```

字号：歌词 40sp、底部曲名 36sp、列表歌名 27sp。

**播控键全部左置**：`◀◀ / 播放 88dp / ▶▶ / 上报 / 顺序 / ♥`。进度条是唯一需要横向距离的控件，放条内右端。

顶栏标签页 6 个：`正在播放 / 歌单 / 收藏 / 全部 / 刷新 / 设置`。「正在播放」是新增的整屏大歌词页（`lyric_base` 40sp，当前句 1.25 倍加粗）。

### 2. 配色：Day-Light（`values/colors.xml` + 10 个 drawable）

底 `#F4F6F9` / 面 `#FFFFFF` / 字 `#111820` / 强调蓝 `#1668C9`。

强调色必须换：原青绿 `#30DDC2` 在白底上只有 **2.2:1** 对比度，换蓝后 **6.1:1**。亮底用纯色而非三段渐变——TFT 车机屏上渐变会看出色带，对可读性没有贡献。

### 3. 夜间档 N3 暖墨琥珀 + 顶栏一键切换

`values-night/colors.xml` 覆盖同名 token（22 个，与白天档一一对应并有脚本断言），布局与 drawable 一行没动。底 `#12100D`、强调 `#E0A15A`——夜间行车时屏幕是车里唯一强光源，蓝成分会压暗视觉，所以整套往琥珀偏。

切换走 `AppCompatDelegate.setDefaultNightMode()`，主题改 `Theme.AppCompat.DayNight.NoActionBar`，在 `ZSpaceApplication.onCreate` 定档避免冷启动闪一帧白底。三档 `自动 / 白天 / 夜间`，自动档 18:00 入夜、06:00 出夜（车机拿不到大灯光控信号，本地时间是最可靠的代理）。

顶栏按钮一键翻观感，文案是「点下去会变成什么」；翻完钉成手动档，否则自动档会在下一个整点把司机刚选的颜色抢回去。换色会重建 Activity，因此加了「记住当前页」，不再把用户弹回歌单网格。

配套把 `LyricAdapter` / `SongAdapter` / `MainActivity` 里的硬编码 hex 全部收口成 `@color` token——不收这个口，夜间就是深底配深字。现在全仓 `Color.parseColor` 为零。

### 4. 删除封面相关代码

`JellyfinApiClient.getCoverUrl()` 拼的地址**从来没带 `api_key`**，也就是说实车从来没有真正加载出过封面；同时这 55 首歌共用同一个 `AlbumId`，列表里根本没有可辨识的封面。整条链路删净：`SongItem.coverUrl` 字段与两个构造参数、`SongDao` 读写、建表语句里的 `cover_url` 列、`bg_cover_placeholder.xml` 与 `@dimen/cover`。

老库残留的空 `cover_url` 列不做迁移删除——Android 4.3 自带的 SQLite 对 `DROP COLUMN` 支持不稳，为一个死列冒升级失败的风险不值当。

### 5. 列表顺序：撤掉错的方向，收成一个来源

**先说探针查出来的事实**（用独立 `DeviceId=MAC-PROBE-LISTORDER` 拉 799 首，没碰车机 token）：

- 服务端 `SortBy=SortName` 返回的序列里，**第 79 位之后严格按歌名升序（0 个反例）**；前 79 首是 `SortName` 未赋值的条目，被无条件顶到最前，它们之间还是引擎自定次序。
- 这个字段在响应里**根本不序列化**，所以客户端无从知道为什么这几首特殊。
- 落到具体歌单：抖音热歌 53 首里有 5 首是浮起项（出山 / 去年夏天 / 可不可以 / 红昭愿 / 一百万个可能），粤语金曲 97 首里有 34 首。
- 顺序在重复请求和不同分页大小（250 / 500）下可复现——所以它稳定，但稳定不等于可解释。

**结论：上一版准备的 `sort_index`（把服务端返回顺序记成唯一真源）方向是错的**，它会让列表开头摆几首毫无规律的歌。本版撤掉它，连带撤掉为伺候这个字段而写的 PRAGMA 列探测与降级分支。

改成 **`util/LibraryOrder.java` 作为全应用唯一定序规则**，SQL 串和 Java 比较器并排放（分开写就会漂移）：`name ASC, id ASC`。

`id` 兜底是必需的：库里 34 组重名共 73 首，光「富士山下」就 5 首。只比 name 时这些行的先后由排序算法决定，两次查询可以不一样。审计时抓到搜索路径 `searchSongs` 还挂着裸的 `"name ASC"`，一并并入。

**队列与列表分叉的两条路径也修了：**

- 自动续播里「上次的歌不在当前分类」原本把队列换成全曲库 799 首，而左边列表还停在分类——这就是「播放不跟左侧列表走」的直接来源。现在不换队列，宁可这次不自动开播，并写 breadcrumb。
- `rebuildQueueFromIds` 原本按持久化的 id 先后保序，那是列表顺序的第二个来源。抽成 `ui/QueueRestore.java`，语义改成**成员由 id 决定、顺序一律跟随池**。

## ⚠️ 行为变化（会察觉到的）

1. **冷启动时如果上次那首歌不在恢复出来的列表里，不再自动开播**，需要手动点一下。以前它会偷偷把队列换成全曲库继续播。
2. 列表顺序变成**严格按歌名**（数字 < 大写 < 小写 < 汉字），和 Jellyfin 网页端把无 SortName 条目顶在最前的显示不再一致。
3. 界面里不再出现任何封面/专辑图。

## ✅ 验证到什么程度

`clean :app:assembleDebug :app:testDebugUnitTest` 通过，**367 条 host JVM 单测全绿**，本版新增 18 条：

- `NightModeManagerTest` 5 条 —— 17/18 点、5/6 点四个换档时刻逐点断言，外加自动档夜间时段合计 12 小时。
- `QueueRestoreTest` 8 条 —— 队列恢复的契约：顺序跟池不跟持久化 id、删掉的歌落选、重映射绝不把队列搞空。
- `LibraryOrderTest` 5 条 —— 同名靠 id 定序（比较器是全序）、播放次数相同时落到 name/id、码点基准、SQL 串带着 id 兜底。

**没做到的**：本版全部视觉结论来自把 XML 按 dp 一比一转写成 HTML 再无头 Chrome 出图，**不是 app 截图**（Mac 侧没有 API 18 / density 1.0 的等价模拟器）。车机上到底几行、裁不裁字、点不点得中，以下面清单为准。

**根因未闭环的一环**：车上实际走的是哪条分叉路径，需要读车机上报（NAS `/opt/data/Jarvis/data/crash-reports/`）才能确认。本次调查环境访问不到 NAS，所以「分叉只有已修的那两条」是代码审计的结论，不是日志证实的结论。

## 🚗 实车验收清单

1. 设置页「检查更新」拉到 v3.2.0 (vc11)，`dumpsys package` 确认 `versionCode=11`。
2. 白天强光下看主界面，确认文字不再被反射洗掉。
3. 数一屏几行（预期 6 行）；若明显不是 6 行，回查真车是否命中 `sw720dp` 档。
4. 左手不越方向盘半径，试 `◀◀ / 播放 / ▶▶ / 上报 / 顺序` 是否都够得到。
5. 拖一次进度条（它在条内右端，是唯一要伸手的控件），确认可接受。
6. 顶栏「夜间」点一下立即翻色，且**翻色后仍停在当前那一页**（不该被弹回歌单网格）。
7. 设置页「夜间模式」三档循环，自动档在 18 点后上车应直接是深色。
8. **列表顺序主验**：进抖音热歌，确认「出山 / 去年夏天 / 可不可以 / 红昭愿 / 一百万个可能」这 5 首按名字排在中间位置，而不是被顶到最前。
9. **队列跟随主验**：在某个歌单里点第 20 首起播，连按「下一首」，确认高亮逐行往下走、不跳位。
10. 冷启动复现一次：播到某歌单中段 → 断电 → 再上车，确认左侧列表就是那个歌单，且没有偷偷变成「全部歌曲」。
11. 夜间档下专门看一眼正在播的那一行高亮和收藏 ♥，确认对比度够（`fav_off` 深色档是 `#4C443A`，偏暗）。
