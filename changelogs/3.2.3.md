## 有意保留不动的两处全线程 dump

判据是「这一刻是否真的需要所有线程的现场」：

- `CrashMonitor.java:247` 主线程卡死看门狗 —— 卡死必须看别的线程停在哪把锁上，且它跑在 watchdog 后台线程，不占主线程；
- `CrashMonitor.java:543` Java 未捕获异常 —— 进程正在死，必须同步抓完整现场，晚一帧就没了。

## 验证

- 新增 host 单测 `CrashReportTest.currentThreadStackDumpCoversOnlyTheCallingThread`：断言 dump 里**只出现一个线程段**、且包含调用帧自身。这条用例的形状就是防回归用的——将来谁把它改回 `dumpAllThreads()`，第二个线程段会让它变红。
- `testDebugUnitTest assembleDebug` 通过，**374 条 host 单测 0 失败**。
- 实车判据（与前两版同批）：升级后 `main_thread_blocked` 中 `initHttpClient` 栈顶应归零；`abnormal_exit` 上报的 `threadDump` 应变为单线程段（内容变短属预期，不是丢证据）。
